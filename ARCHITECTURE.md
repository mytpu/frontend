# «Мой ТПУ» — фронтенд: анализ, архитектура, план

Документ описывает текущее состояние фронтенда, целевую архитектуру и дорожную карту.
Основа решений: бриф проекта, дизайн-макеты (`14-dizain-sajt` — базовый светлый, `15-temy-sajt` —
каталог тем, `12-bek-mcp-panel` — контракты с бэком, `10-moj-tpu-hub` — логика экранов).

## 1. Где мы сейчас

**Стек:** Vite 8 + React 19 + TypeScript 6, oxlint, react-router-dom установлен (но не используется).

## 2. Принципы архитектуры

1. **Модуль = фича.** Каждая фича — вертикальная папка: свой UI, свои хуки, свой API-модуль,
   свои типы, свой CSS. Общее — только `shared`. Так «куда положить файл» всегда имеет один ответ.
2. **Компонент не знает, откуда данные.** Компонент → хук (`useToday()`) → API-модуль.
   Замена мока на реальный бэк не трогает ни один компонент.
3. **Только семантические токены.** Ни одного hex/px-цвета в компонентах — только
   `var(--color-...)`. Это то, что делает 10 тем дешёвыми.
4. **Моки — полноправный источник данных.** Мок-модули реализуют те же функции, что и реальные
   эндпоинты (включая стриминг ответа помощника). Разработка не ждёт бэк.
5. **Минимум зависимостей.** UI — всё своё (по брифу). Добавляем только то, что нельзя
   разумно написать самим: роутер, серверное состояние, при необходимости — drag.

## 4. Подсистемы

### 4.1 Темы — «5–10 миров»: меняется не только CSS

Тема — это **модуль из четырёх независимых слоёв**, а не файл с цветами. Слои можно
комбинировать: тема может перекрасить всё, а может полностью перестроить страницу.

| Слой | Что меняет | Формат | Обязателен |
|------|-----------|--------|-----------|
| 1. Токены | цвет, радиусы, тени, шрифты, характер движения | CSS-файл | да |
| 2. Декор | фоновый «мир»: градиенты, blur, параллакс, позже 3D-сцены | компонент-слой под контентом | нет |
| 3. Каркас (shell) | композиция страницы: где навигация, какой формы контейнер, как разложены блоки | вариант раскладки слотов | нет |
| 4. Скины виджетов | форма конкретного виджета: лента пар ↔ «окно» ↔ бумажный блок | переопределение view-компонента | нет |

```ts
// shared/theme/ThemeDef.ts
interface ThemeDef {
  id: string;
  name: string;
  preview: string[];                              // цвета карточки в переключателе
  tokens: string;                                 // css-файл с перекрытием токенов
  decor?: ComponentType;                          // фоновый «мир» под контентом
  shell?: ShellId;                                // 'sidebar' | 'bottom-nav' | 'floating' | …
  widgetSkins?: Partial<Record<WidgetKind, ComponentType>>; // скины вида виджетов
  transition?: 'morph' | 'fade' | string;         // характер смены темы (см. ниже)
}
```

Механика:

- **`AppShell` — контракт, а не вёрстка.** Он определяет *слоты* (навигация, шапка,
  контент, вызов помощника, карточка пользователя), а раскладку рендерит **shell
  активной темы**: боковое меню, нижняя панель, плавающие панели, центральная колонка.
  «Retro Windows» раскладывает виджеты «окнами» с тайтл-барами, «Origami» — скошенными
  бумажными блоками со своими размерами сетки. Расположение и композиция — на этом слое.
- **Данные отделены от вида.** Виджет = общий хук данных + view-компонент, который тема
  может подменить через `widgetSkins`. Поэтому 10 тем × 6 виджетов не пишутся 10 раз:
  скины пишутся только там, где теме действительно нужна другая форма, остальные
  наследуют дефолтный вид.
- **Правило полноты:** тема обязана уметь показать всё, что умеет дефолт (все виды
  виджетов, вся навигация) — меняться может форма, но не состав возможностей.

Лестница сложности тем (по ней и строим по порядку):

- **Графит** — только токены (тёмная перекраска);
- **Стекло** — токены + декор-слой (цветные пятна света и blur под контентом);
- **Origami / Retro Windows / Cyberpunk** — токены + декор + свой shell + скины + свой
  характер перехода.

**Анимация переключения.** Тема меняет и DOM-структуру (не только классы), поэтому
обычный CSS-transition переход не покроет. Используем **View Transitions API**:
`setTheme()` оборачивается в `document.startViewTransition(...)` — браузер снапшотит
старый экран и морфит его в новый: панели сами плавно разъезжаются на новые места,
а не просто fade. Каждая тема задаёт характер перехода правилами для
`::view-transition-old/new` (оригами «складывается», retro «выдвигает окно»,
cyberpunk — глитч-сдвиг). Браузеры без поддержки API получают graceful fade через
CSS-класс — переключение работает везде, анимация — progressive enhancement.

`ThemeProvider`: выбор в localStorage, по умолчанию следует `prefers-color-scheme`;
токены движения (`--dur-*`, `--ease-*`) — часть темы наравне с цветом.

### 4.2 Свой UI-kit (`shared/ui`)

Ручной, только на токенах, по макетам. Минимальный состав:

`Button` (primary/secondary/ghost/light, sm) · `IconButton` · `Chip` (green/warn/info/grey/dark) ·
`Card` · `WidgetShell` (единая рамка виджета: иконка + заголовок + ссылка + контент) ·
`Skeleton` · `ThinkingDots` (пульсирующий индикатор «помощник думает» — вместо спиннера) ·
`Input` · `Kbd` · `Drawer` · `Modal` · `Avatar` · `EmptyState` · `SourceBadge` (источник
уведомления: почта/Moodle/расписание/заявки/оценки).

Иконки — свой SVG-спрайт (взамен шаблонного `icons.svg`) + компонент `Icon`.
Витрина всего — страница `/dev/ui`: видно поломку темы/токена сразу,dependency-free замена Storybook.

### 4.3 Слой данных

```
Компонент → хук фичи (useQuery) → api-модуль фичи → shared/api/http.ts
                                                        ↘ mock-switch: real | mocks/
```

- `http.ts`: `fetch` c `credentials: 'include'` (сессия — HttpOnly cookie от бэка),
  базовый URL из `VITE_API_BASE`, типизированные ошибки (401 → редирект на вход).
- Серверное состояние — **TanStack Query**: каждый виджет — свой query-ключ
  (`['today']`, `['deadlines']`, …) → параллельная загрузка, скелетоны, рефетч.
  Локального стора (Redux/Zustand) на старте нет: состояние чата — reducer внутри фичи,
  конфиг доски и тема — хуки над localStorage.
- Монолит `HomeSummary` разбираем на ресурсы: `me`, `today`, `deadlines`, `grades`,
  `event`, `inbox`, `tickets`.

### 4.4 Помощник — SSE-стриминг

Бэк отдаёт ответ потоком SSE-событий (`12-bek-mcp-panel`): `status`, `delta`, `card`,
`relink`, `done`. `shared/api/sse.ts` — клиент на `fetch` (POST с телом + чтение потока),
эмитит типизированные события. В `mocks/` — генератор мок-стрима с задержками,
так что «думает — пульсирует», печатающийся текст и шаги разрабатываем сразу.

`streamReducer` собирает состояние треда:

| Событие | Эффект в UI |
|---------|-------------|
| `status` | шаг «Посмотрел расписание ✓ / Проверил дедлайны…» (пульс на текущем) |
| `delta` | приращение текста ответа (стриминг) |
| `card` | карточка подтверждения: поля черновика + Отправить/Изменить/Отмена |
| `relink` | баннер «нужен повторный вход ТПУ» + кнопка |
| `done` | финализация сообщения, снятие «думает» |

Карточка подтверждения — первоклассный компонент: «ничего не отправится без вашего
нажатия», таймер жизни черновика. Правая колонка «Что использовал / Ждёт решения»
читает то же состояние.

### 4.5 Доска: реестр + конструктор

- `registry.ts`: `Record<WidgetKind, { component, sizes, title, icon }>` — добавить виджет =
  папка в `widgets/` + строка в реестре + описание в каталоге.
- Конфиг: `{ id, kind, size }[]` — в localStorage, с бэком `GET/PUT /api/me/board`.
- Режим правки: рамки, переключатель S/M/L, удаление, каталог справа, drag-переупорядочивание
  (сначала кнопками ↑↓, drag — позже, при необходимости `@dnd-kit`).
- Сетка из макета: S = 1 колонка, M = 2, L = 2×2; при <1200px — 3 колонки,
  <900px — мобильная раскладка (виджеты в столбик, S — половина ширины).

### 4.6 Авторизация (Keycloak)

Веб-клиент не работает с токенами сам: вход — редирект на бэк → Keycloak → oauth.tpu.ru →
назад; сессия — HttpOnly cookie. Фронту нужно:

- при старте `GET /api/me` → `AuthContext` (пользователь, группа, роль) или `null`;
- `ProtectedRoute`: нет пользователя → редирект на `/login` бэка;
- «Выйти» — POST на бэк; 401 в `http.ts` — сброс состояния и редирект.
- Мок: `/api/me` возвращает фиксированного студента.

### 4.7 «Живость» и глубина

- Сначала CSS: переходы на `--dur/--ease`, keyframes (пульс, появление), stagger-появление
  виджетов доски, `prefers-reduced-motion` — обязательный респект.
- Смена страницы — View Transitions API (progressive enhancement).
- Параллакс-слои темы (мышь/скролл → transform через rAF) — изолированный эксперимент в
  `shared/motion/`, подключается темой как декор-слой. 3D-переходы «внутрь картинки» —
  перспектива после этапа 7, каркас к этому уже готов (декор-слой + motion-токены).

## 5. Стек: что добавляем, что нет

| Решение | Выбор | Почему |
|---------|-------|--------|
| Роутер | `react-router-dom` (уже стоит) | стандарт, вложенные роуты |
| Серверное состояние | **TanStack Query** | кэш, скелетоны, рефетч — убирает 80% ручного кода |
| UI-киты (MUI, Ant…) | ❌ | по брифу — всё руками, свой kit на токенах |
| CSS | **plain CSS-файлы на компонент** (как сейчас) | учиться читать CSS важнее, чем тянуть CSS-in-JS; темам нужны глобальные переменные |
| Drag&drop | сначала свой простой, при необходимости `@dnd-kit` | поведение, не визуал — допустимая зависимость |
| Тесты | **Vitest + React Testing Library** (редьюсеры, хуки, примитивы), позже Playwright-smoke | дёшево, полезно для обучения |
| MSW | опционально на этапе 7 | мок-модули уже дают подмену; MSW — если захотим перехват реальных URL |

Скрипты: `dev / build / lint / typecheck / test` — Степан подключит их в CI как есть.

## 6. Дорожная карта

Этапы идут последовательно, каждый заканчивается «демонстрируемым» состоянием.
Размер: S ≤ недели, M ≈ 1–2 недели, L — по обстоятельствам.

**Этап 0 — Фундамент (S).** Чистка и каркас.
Фикс `--color-muted-2` → `--color-ink-2`; роутер + `AppShell` (один каркас, чат внутри него);
алиас `@/`; Onest в `index.html`, `lang="ru"`, титул; нормальные мок-данные; удалить
шаблонные иконки/файлы; README под проект.
*Готово, когда:* страницы открываются по URL, lint + typecheck зелёные, тёмная тема переключается.

**Этап 1 — Дизайн-система (M).** `shared/ui` + иконки + `WidgetShell` + скелетоны + `/dev/ui`.
*Готово, когда:* все элементы макета «Главная» собираются из примитивов, `/dev/ui` выглядит
аккуратно в светлой и тёмной темах.

**Этап 2 — Доска на моках (M).** Все 6 виджетов на своих query, скелетоны/пустые состояния,
адаптив 4→3→1. Данные из разрезанных ресурсов.
*Готово, когда:* экран «Главная» = макет `14-dizain-sajt`, доска живёт на конфиге.

**Этап 3 — Темы (M).** Механизм + Светлая ТПУ / Графит / Стекло + переключатель в профиле.
*Готово, когда:* три темы переключаются на лету, в компонентах ни одного hex (проверка грепом).

**Этап 4 — Помощник (L).** Мок-стрим: стриминг текста, шаги, пульс «думает», карточки
подтверждения, история чатов, три колонки по макету.
*Готово, когда:* сценарий «пары завтра» и «письмо преподавателю» проигрываются от мока
без отличий от будущего реального стрима.

**Этап 5 — Конструктор доски (M).** Режим правки, размеры, каталог, персист конфига.
*Готово, когда:* изменения переживают перезагрузку, драг не ломает сетку.

**Этап 6 — Остальные экраны (M).** Сервисы (каталог + SSO-баннер), Профиль (подключения,
темы, уведомления), drawer уведомлений, палитра поиска Ctrl+K.
*Готово, когда:* все 4 раздела навигации живут, уведомления открываются поверх любой страницы.

**Этап 7 — Интеграция с бэком (L).** Переключение моков на реальные эндпоинты (`/api/me`,
расписание, чат SSE, подтверждения), вход/выход Keycloak, vitest, CI-скрипты Степану.
*Готово, когда:* приложение работает на реальном бэке без правок компонентов.

**Перспектива:** параллакс/3D-миры, остальные темы из каталога 15-ти, PWA/мобильная
раскладка <900px, View Transitions между страницами.

## 7. Соглашения

- **Именование:** компоненты — `PascalCase.tsx`, хуки — `use-thing.ts`, CSS-файл рядом:
  `Component.css`; классы БЭМ-подобные (`board__cell--M`) — уже сложилось, сохраняем.
- **Импорты:** только через `@/…`; относительные — внутри своей папки.
- **Цвета/шрифты/движение:** только `var(--…)` из семантических токенов. Hex в компоненте = баг.
- **Данные:** компонент → хук → api. Прямой `fetch` в компоненте = баг.
- **Типы:** контракт ответа живёт в api-модуле фичи; в `shared` — только кросс-доменное.
- **Ветки:** `main` защищён; работа в `feature/…` ветках, мердж после lint+typecheck.

### Чек-лист «добавить виджет»

1. Папка `features/board/widgets/<name>/`: `XWidget.tsx`, `XWidget.css`, `useX.ts`.
2. Тип kind + строка в `registry.ts` (компонент, размеры, заголовок, иконка).
3. API-функция + мок в `mocks/`.
4. Обёртка `WidgetShell`, скелетон и пустое состояние обязательны.
5. Строка в каталоге виджетов (для конструктора).

### Чек-лист «добавить тему»

1. `theme/themes/<name>/tokens.css` — обязательно; `decor.tsx`, shell, `widgetSkins` —
   если теме нужен другой «мир», а не только цвета.
2. `ThemeDef` в реестре тем: id, название, превью-цвета, shell, характер перехода.
3. Скины — только view-компоненты; хуки данных общие, менять их в теме нельзя.
4. Проверить `/dev/ui` и главную: контраст, тени, и переход при переключении темы
   (в т.ч. в браузере без View Transitions).

## 8. Что фронт ждёт от бэка (предложение контрактов)

Для Степана и Владимира — минимум, закрывающий этапы 2–7:

```
GET  /api/me                       # профиль: имя, группа, институт, роль
GET  /api/schedule/today           # пары дня (+ статус переноса)
GET  /api/deadlines                # ближайшие дедлайны (Moodle)
GET  /api/grades                   # последние оценки + средний
GET  /api/events/nearest           # ближайшее событие ТПУ
GET  /api/inbox                    # сводка почта/Moodle/расписание
GET  /api/tickets                  # заявки help.tpu.ru
GET  /api/chats                    # список разговоров
GET  /api/chats/{id}/messages      # история
POST /api/chats/{id}/messages      # → SSE-поток: status|delta|card|relink|done
POST /api/pending/{actionId}/confirm | /cancel
GET/PUT /api/me/board              # конфиг доски
```

Формат дат — ISO 8601 (UTC); лейблы («завтра», «пт») фронт делает сам — это язык интерфейса,
не данных.

# Что делать дальше

Состояние на 18 ноября. Каркас, доска, каталог сервисов, профиль и помощник на реальном потоке шлюза
готовы; `npm run build`, `npm run lint`, `npm test` зелёные.

## 1. Подключить стенд помощника

`ASSISTANT_URL` и `ASSISTANT_KEY` в `.env.local` (см. `.env.example`). Без них чат показывает ошибку
шлюза и кнопку «Повторить» — это рабочий путь, но не показ.

## 2. Заменить демо-данные доски на API

Меняется только `src/api/client.ts`, экраны не трогаем. Что и откуда:

| Экран | Источник |
|---|---|
| студент, группа, институт | `lk.tpu.ru` |
| пары на день и неделю | `rasp.tpu.ru` (`rasp_day`/`rasp_week` отложены до разрешения ТПУ) |
| дедлайны | `lms.tpu.ru` (Moodle) |
| письма | `mail.tpu.ru` |
| заявки | `help.tpu.ru` |

Правило: в интерфейсе только настоящие поля. Не пришло поле — виджета нет, а не «пример из макета».
Чип «демо» снимается в `WidgetFrame` и на экране расписания одновременно с подключением API.

## 3. Заявка: от черновика к отправке

Сейчас черновик сохраняется в браузере и подтверждается отдельным шагом. Когда появится API
`help.tpu.ru`, подтверждение станет вызовом шлюза: черновик → `POST` заявки → номер и статус
приходят из ответа. Точка входа — `src/assistant/DraftCard.tsx`, `confirm()`.

## 4. После identity (спецификация 4)

- Выход с отзывом сессии на сервере (`Профиль` → «Сессия»).
- «Приложения с доступом» — реальные разрешения вместо демо-списка.
- Лимиты и история диалога по пользователю: сейчас контекст держит шлюз 30 минут.

## 5. Полировка

- Состояние «нет доступа» на экранах, когда права проверяет бэкенд.
- Переходы между экранами через View Transitions (только при `prefers-reduced-motion: no-preference`).
- Нагрузочная проверка палитры на 200+ элементах, если каталог сервисов вырастет.

## Заметки

- Темы: светлая по умолчанию, «Графит» — тёмная; значения в `src/design/tokens.css`.
- Демо-состояния для показа: `?state=moodle-down`, `?state=empty`.
- Локальная заглушка шлюза: `npm run stub`, контракт тот же, что у `services/assistant`.
